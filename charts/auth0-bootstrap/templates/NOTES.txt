{{- if .Values.bootstrap.enabled }}
Auth0 Bootstrap Job has been created!

The bootstrap job will:
- Authenticate with the Auth0 Management API ({{ .Values.auth0.domain }})
- Create the API with its custom permissions/scopes: {{ .Values.auth0.api.name }} ({{ .Values.auth0.api.identifier }})
- Configure applications:
   - Frontend (SPA): {{ .Values.applications.frontend.name }}
   - Backend (M2M): {{ .Values.applications.backend.name }}
   - Worker (M2M): {{ .Values.applications.worker.name }}
- Grant M2M applications access to the API (and the backend limited Management API access)
{{- if .Values.users.admin.enabled }}
- Create admin user: {{ .Values.users.admin.email }}
{{- end }}
{{- if .Values.users.testUsers.enabled }}
- Create {{ len .Values.users.testUsers.users }} test user(s)
{{- end }}
{{- if .Values.actions.enabled }}
{{- if .Values.actions.postLogin.enabled }}
- Create, deploy, and bind the post-login Action: {{ .Values.actions.postLogin.name }}
{{- end }}
{{- if .Values.actions.clientCredentialsExchange.enabled }}
- Create, deploy, and bind the credentials-exchange Action: {{ .Values.actions.clientCredentialsExchange.name }}
{{- end }}

The Actions read their JS source from the ConfigMap {{ .Values.actions.sourceConfigMap.name }},
which scripts/auth0/bootstrap-auth0.sh creates from scripts/auth0/actions/. If you
install this chart directly, create that ConfigMap first or set actions.enabled=false.
{{- end }}

To check the job status:
  kubectl get jobs -l "app.kubernetes.io/name={{ include "auth0-bootstrap.name" . }},app.kubernetes.io/instance={{ .Release.Name }}"

To view the job logs:
  kubectl logs -l "app.kubernetes.io/name={{ include "auth0-bootstrap.name" . }},app.kubernetes.io/instance={{ .Release.Name }}"

IMPORTANT: After the job completes, retrieve the M2M client secrets from the job logs
and create the required Kubernetes secrets before deploying the guardian-platform chart.

{{- else }}
Auth0 Bootstrap is disabled. To enable it, set bootstrap.enabled=true
{{- end }}
